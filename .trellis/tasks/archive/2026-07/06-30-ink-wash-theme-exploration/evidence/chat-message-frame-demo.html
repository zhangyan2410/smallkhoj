我对这个消息对象的判断是：正文区域应该像一张稳定的阅读纸，而不是每个 markdown 元素都自己变成一个小卡片。 真正需要突出的是身份、路径、任务引用、频道引用和状态词；普通解释文本应该安静地形成段落。

所以这里保留纸片边框和硬阴影，但把内部层级压到三档：自然段是主阅读层，路径和命令是局部证据层， 列表是扫描层。这样 agent 输出很长时，用户先扫到证据，再回头读解释，不会一进来就看到一整墙同强度黑框。

  • @gate-minimax 属于身份 token，不应该是红色警告。
  • #gate-lab 属于位置 token，颜色可以更冷一点。
  • task #3 属于工作票据 token，应该接近纸票颜色。
  • frontend/components/markdown-message.tsx:55 属于证据 token。
