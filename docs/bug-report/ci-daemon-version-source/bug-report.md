# CI Daemon version source drift

## Bug diagnosis capsule

| Field | Content |
| --- | --- |
| **1. Symptom** | GitHub source-hygiene fails during WebDriver test import because its clean Python environment lacks declared dependencies. When run on a workstation with ambient packages, the delivery contract instead fails because CI release-version literals are older than the Daemon package; Backend and Daemon suites also fail on copied current-version expectations. Expected: one package version edit propagates to CI and current-release tests, and a clean runner provisions every imported dependency. |
| **2. Evidence** | GitHub run `30817948692` reports `ModuleNotFoundError: No module named 'requests'` in `agent/daemon/webdriver/twd.py`. Locally, `make scripts-test` fails because package `0.2.3` differs from workflow `0.2.1`; Backend focused tests pass 4/6 because generated URLs use `0.2.3`; the complete Daemon suite passes 281/283 because payloads use `0.2.3` while two test handlers expect `0.2.2`. |
| **3. Confirmed root cause** | The current Daemon release version was copied into CI and test fixtures instead of derived from `agent/daemon/aaa-daemon/package.json`. The source-hygiene job also invoked WebDriver tests without installing their existing `requirements.txt`, so local ambient packages masked the clean-runner contract. |
| **4. Diagnostic strategy** | Trace package metadata through CI env, delivery validation, Backend command generation, and Daemon connect/register payloads. First replace the delivery test's literal-version requirement with a contract that rejects literals and requires package-derived `$GITHUB_ENV` exports; separately require WebDriver requirements provisioning before `make scripts-test`. Observe both tests RED before changing the workflow. |
| **5. Timeout strategy** | If dynamic export cannot be expressed and validated in one focused workflow/test iteration, stop and introduce a small repository-owned exporter rather than duplicating parsing logic. If a full gate exposes a behavior failure beyond version or dependency setup, keep it red and split that distinct defect instead of weakening this contract. |
| **6. Warning strategy** | Reject fixes that merely replace `0.2.1`/`0.2.2` with `0.2.3`, derive `MINIMUM_DAEMON_VERSION` from the release package, import the production version constant as the test oracle, skip WebDriver tests, or rely on packages already installed on a developer machine. |
| **7. User-visible correction** | No product UI changes. Contributors can bump the Daemon package version once without manually synchronizing CI and current-release test fixtures; PR checks fail for real contract drift rather than stale copies or missing ambient dependencies. |
| **8. Acceptance** | Focused delivery contracts first fail for missing package-derived exports and missing requirements provisioning, then pass after the workflow fix. Backend current-release tests, complete Daemon tests, complete scripts tests, Backend CI, Integration Gate, Compose schema, and diff checks pass before merge. |
