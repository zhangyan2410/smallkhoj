# 修复：退出后无法登录第二个账号（setup 死锁）

## 根因

应用有两套会话，`logoutAction()` 只清了其中一套：
- **A. SmallKhoj 会话** — cookie `smallkhoj_session`。`logoutAction` 清的就是它（`server-auth.ts:91-95`）。
- **B. better-auth 会话** — cookie `better-auth.session_token`。登出时**没清**（全仓未调 `auth.api.signOut`）。

退出链路 → 卡死：
1. 用户点"退出登录" → `logoutAction` 清 A，跳 `/login`（`server-actions.ts:53-57`）。
2. `/login` 渲染时：`currentAccount()` 看 A → A 已清 → 不跳转（`login/page.tsx:187,191`）；接着 `auth.api.getSession()` 看 B → **B 还在** → `setupUser` 非空 → 强制 `mode="setup"`（`login/page.tsx:194-202`）。
3. setup 模式只渲染"确认不可变名字"输入框，**隐藏邮箱/密码框**（`page.tsx:239`），**隐藏"已有账号？登录"切换链接**（`page.tsx:268` `{mode !== "setup" ? ... : null}`）。
4. 用户看到的正是截图里那个页面 → 没有任何登录第二个账号的入口 → 卡死。

## 修复方案（根治 + 逃生口，两层防护）

### 改动 1 — 根治登出：`logoutAction` 同时清 A + B

**文件：`frontend/app/server-actions.ts:53-57`**

`logoutAction` 改为：先调 `auth.api.signOut({ headers })`（删 better-auth DB session + 删 B cookie），再调 `clearSessionCookie()`（清 A cookie），最后 redirect。

- `auth.api.signOut` 确认是 `requireHeaders: true` 的 POST 端点（`node_modules/better-auth/dist/api/routes/sign-out.mjs`），会调用 `deleteSessionCookie(ctx)` 删 B cookie + `internalAdapter.deleteSession` 删 DB session，是最彻底的登出。
- 需要 `import { headers } from "next/headers"` 和 `import { auth } from "@/lib/auth"`。
- 用 try/catch 包 `auth.api.signOut`：即使 B session 已失效/cookie 脏了，也不阻断 A 的清理和跳转（fail-open 到登录页才是期望行为）。
- 改后 `/login` 的 `setupUser` 判定会返回 null → 正确回到 signin 模式 → 显示登录入口。

### 改动 2 — 逃生口：setup 页加"切换账号"链接（防 B 残留卡死）

**文件：`frontend/app/login/page.tsx:268-281`** + 新 server action

即使改动 1 修好了，B 仍可能因其他原因残留（多标签、脏 cookie、过期 DB session 未同步）。在 setup 模式下补一个"用其他账号登录"入口，点击后强制清 A+B 再回 signin。

- 在 `server-actions.ts` 新增 `switchAccountAction()`：调 `auth.api.signOut({ headers })`（try/catch）+ `clearSessionCookie()` + `revalidatePath("/", "layout")` + `redirect("/login?mode=signin")`。复用与 `logoutAction` 相同的清理逻辑。
- 在 `login/page.tsx` setup 模式分支里渲染一个 form（`action={switchAccountAction}`），文案 `t("login.switchAccount")`。放在卡片底部，与现有 signin/signup 切换链接位置对应。
- 复用现有 `<form action={...}>` + `<Button>` 模式（与 `server-switcher.tsx:120` 一致），不引入新组件。
- 这个逃生口在 setup 死锁时立即可用，无需用户理解两套会话。

### 改动 3 — i18n：新增 `login.switchAccount` 文案

**文件：`frontend/messages/zh-CN.json` + `frontend/messages/en.json`**（`login` 块内，`finishSetup` 附近）

- zh-CN：`"switchAccount": "用其他账号登录"`
- en：`"switchAccount": "Use a different account"`

### 改动 4 — 测试：扩展 login bootstrap 契约测试

**文件：`frontend/test/login-bootstrap.test.ts`**

- 加断言：源码含 `switchAccountAction` 引用、setup 模式下渲染了切换账号入口（如 `switchAccount` 文案 / form）。
- **新文件 `frontend/test/logout-clears-both-sessions.test.ts`**：源码契约测试，断言 `server-actions.ts` 中 `logoutAction` 同时调用 `auth.api.signOut`（或引用）和 `clearSessionCookie`，且 `signOut` 在 try/catch 内（不阻断清理）。遵循现有源码文本断言风格（`login-bootstrap.test.ts` 的 `readFile` + `assert.match` 模式），不启动真实 better-auth/DB。

## 验证

focused check（local fast path，单条命令）：`cd frontend && npm test -- logout-clears-both-sessions login-bootstrap`（或现有 frontend test runner 等价命令）。不跑完整 E2E/浏览器验收（非 UI 必要项，且登出真实链路已在产品里复现过）。

## 不做的事

- 不引入 `middleware.ts`（现有 layout gate 已够，问题不在路由保护）。
- 不改 better-auth cookie 前缀/配置（`auth.ts` 保持现状）。
- 不动 `(app)/layout.tsx` 的 auth gate（它看 A 是正确的）。
- 不动 `loginAction` 的 setup 提交流程（那是 onboarding 正常路径，不是本次 bug）。
- 不做远程发布/PR/CI（contained local fix）。
