# Agent Avatar and Status UI

## Goal

Build a reusable member avatar/status UI so agents and humans are visually identifiable across DMs, member lists, profile pages, and future chat surfaces.

The product direction is:

- Agent avatars are generated by the system, not uploaded manually.
- Initial agent avatar engine is DiceBear using the `croodles-neutral` style.
- Agent avatar images may be pre-generated/cached; runtime UI must not wait on AI image generation.
- AI image generation may be used later for style references or future custom packs, but not in the MVP runtime path.
- Human/user avatars can be uploaded or set by URL.
- Status indicators use one shared mapping so adding states or changing colors later is low-cost.
- Do not add runtime/provider badges in this task.

## Confirmed Facts

- `frontend/lib/control-plane.ts` already defines `Member`, `MemberProfile`, `statusLabel()`, and `dotClass()`.
- `Member` already exposes `avatarUrl` and `profile.avatarUrl`, which can support human avatar URL/upload metadata.
- `frontend/app/members/page.tsx` currently builds member rows/profile avatars locally and shows a separate status dot before the avatar.
- DMs already show online/offline status, but status freshness depends on realtime member updates and should use the same shared status presentation.
- Browser realtime events already exist, so this task should reuse the existing refresh/event path instead of inventing a separate polling system.
- DiceBear supports deterministic generated SVG avatars from a seed and includes the `croodles-neutral` style.

## Requirements

- Create a reusable frontend avatar component for members/agents.
- Put the status indicator on the avatar's top-right corner.
- Use one central status-to-visual mapping for all avatar status dots.
- Preserve existing status labels and support current states such as `online`, `offline`, `active`, `running`, `idle`, `pending_start`, `starting`, `busy`, `failed`, `crashed`, `stopped`.
- Agent avatars must be generated deterministically from stable data such as `member.id`, `member.handle`, or `member.name` using DiceBear `croodles-neutral`.
- Prefer local DiceBear package generation or pre-generated/cached image assets over depending on DiceBear's remote API in production.
- Human avatars may use `profile.avatarUrl` or `avatarUrl`; if absent, fall back to a generated/initials avatar.
- Add product support for human avatar upload or URL configuration, but do not expose upload/URL controls for agent avatars.
- Reuse the avatar component in the DMs/member surfaces touched by this task rather than leaving separate local implementations.
- Ensure DMs/member lists update status through the existing realtime event/refresh mechanism where available.
- Do not add runtime/provider small badges to the avatar in this task.
- Do not add online AI-generated avatar creation in this task.

## Acceptance Criteria

- [x] There is a reusable frontend member/avatar component used by members list/profile and chat/DM participant surfaces.
- [x] Status dot is rendered on the avatar's top-right corner and uses a centralized mapping rather than page-local color logic.
- [x] Agent avatar fallback is deterministic and system-generated with DiceBear `croodles-neutral`; two renders of the same agent produce the same avatar.
- [x] Runtime UI never calls an AI image generation service or waits for avatar generation.
- [x] Production implementation does not require DiceBear's hosted API when a local package or pre-generated asset path is available.
- [x] Human avatar displays `profile.avatarUrl`/`avatarUrl` when set and falls back cleanly when absent.
- [x] Human avatar upload or URL entry is represented in the product/API plan or implemented if the task is taken beyond UI-only scope.
- [x] Agent creation/edit UI does not ask the user to upload or paste an agent avatar URL.
- [x] DMs no longer depend on stale one-time status rendering when realtime member status events are available.
- [x] No runtime/provider badge is added to the avatar.
- [x] `npm run lint` and `npx tsc --noEmit` pass in `frontend`.
- [x] Browser verification with project WebDriver (`./twd`) shows avatar/status behavior on at least one members page and one chat/DM surface.

## Out of Scope

- Runtime/provider badge on avatars.
- Online AI-generated custom avatar prompts.
- Custom DiceBear style packages.
- Full profile settings redesign.
- Replacing the backend member model unless needed for human avatar upload/URL persistence.

## Notes

- Preferred implementation direction: start with a reusable component and shared status mapping in `frontend`, use DiceBear `croodles-neutral` for deterministic agent avatars, then only add backend/API changes if human avatar URL/upload persistence is missing.
- AI-generated images can be used later as reference material for a custom SmallKhoj avatar pack, but that is separate from this MVP.
- Use project WebDriver policy for visible UI verification; do not use Playwright for this repository.
