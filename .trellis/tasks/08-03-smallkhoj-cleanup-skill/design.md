# Technical design: safe SmallKhoj cleanup skill

## Architecture

Create one project-local skill with a small routing document and a deterministic Python implementation:

```text
.agents/skills/smallkhoj-cleanup/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   └── cleanup-policy.md
└── scripts/
    ├── cleanup.py
    └── test_cleanup.py
```

- `SKILL.md` defines when to invoke the capability, the mandatory audit-before-apply flow, authorization boundary, and reporting contract.
- `cleanup.py` owns discovery, classification, plan generation, revalidation, deletion, redaction, and output formatting. Use only the Python standard library plus read-only system executables discovered at runtime.
- `cleanup-policy.md` records the allow-list, report-only categories, threshold rationale, and operator interpretation without duplicating implementation details.
- `test_cleanup.py` exercises the deletion boundary in temporary directories. Live-project tests remain audit-only.
- `agents/openai.yaml` is generated by `skill-creator` tooling and exposes only `display_name`, `short_description`, and a `$smallkhoj-cleanup` default prompt.

The skill is project-local and absent from `.trellis/.template-hashes.json`, so `trellis update` must not own or overwrite it.

Implement it inline in the current worktree per the user’s explicit choice. This changes versioned project tooling but not application runtime code. Protect the dirty shared worktree by restricting all edits and validation diffs to `.agents/skills/smallkhoj-cleanup/` and `.trellis/tasks/08-03-smallkhoj-cleanup-skill/`.

## Reference cleanup rehearsal

Before initializing the skill, perform one manual cleanup using the same intended safety model:

1. collect fresh disk, Git worktree, process-cwd, open-file, and candidate-stat evidence;
2. separate exact eligible paths from active, dirty, uncertain, and report-only paths;
3. obtain approval for the immutable target list;
4. repeat the decisive checks immediately before deletion;
5. delete only those exact paths;
6. reconcile path absence, disk availability, active service health, and unrelated Git status;
7. update the design/tests with lessons from the real operation.

The rehearsal is an operational prerequisite, not execution of the unfinished skill. It must not be used to relax the eventual plan-ID and revalidation contract.

## One-time local Git retirement pass

After the artifact rehearsal is reconciled, audit registered worktrees and local branches separately from the skill's generated-artifact allow-list. For each worktree, collect cleanliness, branch/tip, active process-cwd ownership, upstream/ahead state, and merge evidence. Because this repository commonly squash-merges, do not rely solely on commit ancestry or `git branch --merged main`.

Accept a local worktree/branch for retirement only when all safety predicates pass and merge proof is strong: direct ancestry, a merged PR to `main` whose head SHA matches the local tip, or a verified content-equivalence result. Remove the exact clean worktree first, then delete only its exact local branch. Keep remote branches unchanged. Preserve and report every ambiguous, dirty, active, detached, unpushed, or locally divergent candidate.

This is a one-time operator-authorized cleanup. The resulting `$smallkhoj-cleanup` MVP continues to classify Git worktrees and branches as report-only.

## Rehearsal results and design corrections

- The exact generated-artifact pass deleted eight approved paths totaling 13,050,252,202 logical bytes. Filesystem availability increased by about 12.22 GiB, all targets were absent afterward, unrelated Git status was unchanged, and both local services remained HTTP 200.
- Cache staleness must use the newest non-symlink descendant mtime, not only the root directory mtime. Directory mtime does not prove that contained cache files have been inactive for 24 hours.
- Candidate fingerprints and expected-byte reports must traverse without following symlinks and include the deterministic tree aggregate used during apply revalidation.
- Expected logical or allocated bytes are estimates; APFS clone/compression behavior and concurrent writes mean free-space delta is reconciliation evidence, not a per-candidate accounting source. The Git pass illustrated this: six worktrees measured about 6.09 GiB with `du`, while free space increased by about 3.36 GiB.
- `lsof` returning exit 1 with empty stdout/stderr represented “no opener/cwd owner” on this host. Any other return/output combination remains a blocker.
- The separate Git audit reduced registered worktrees from 41 to 35 and local branches from 57 to 37 without force deletion or remote-ref changes. It reinforced keeping Git mutation outside the skill MVP.
- Reference projects support the existing project-local skill source model and concise progressive disclosure. No registry, manifest, scheduler, or cross-platform sync layer is needed for this capability.

## CLI contract

### Audit

```text
python3 scripts/cleanup.py audit \
  --repo <smallkhoj-worktree> \
  [--plan-out <plan.json>] \
  [--json]
```

Audit is the default subcommand when none is supplied. It performs read-only discovery. `--plan-out` writes only the requested plan artifact; it does not mutate cleanup targets.

Exit behavior:

- `0`: audit completed, including when nothing is eligible;
- non-zero: repository identity or required safety discovery failed;
- unavailable optional collectors appear as limitations in a successful report when they do not affect deletion eligibility.

### Apply

```text
python3 scripts/cleanup.py apply \
  --repo <same-worktree> \
  --plan <plan.json> \
  --confirm <plan-id> \
  [--json]
```

Apply loads rather than regenerates the candidate set. It must:

1. parse and validate the plan schema;
2. verify the requested repository identity matches the plan;
3. verify `--confirm` exactly equals the plan ID;
4. re-run all ownership and eligibility checks for every deletion candidate;
5. compare every stat fingerprint to the audit fingerprint;
6. abort before any deletion if one candidate fails;
7. delete only allow-listed candidate roots using Python APIs;
8. report actual results and bytes.

The script must not infer authorization from a skill invocation or an old plan. `SKILL.md` requires the agent to show the current plan and obtain current user approval before calling apply.

## Repository and worktree identity

Resolve `--repo` and require:

- a Git worktree (`git rev-parse --show-toplevel` succeeds);
- `.trellis/` and the SmallKhoj project markers needed by this skill;
- membership in `git worktree list --porcelain` for the main repository;
- a canonical real path with no symlink traversal for cleanup targets.

Record the main Git common directory, requested worktree root, HEAD, branch/detached state, and registered worktree roots in the plan. Never derive scope from a broad `/Users/code/project/smallkhoj*` glob.

## Discovery adapters

Implement small adapters that return structured results rather than shell-formatted text:

- Git: `git worktree list --porcelain`, `git status --porcelain`, branch and HEAD.
- Processes: `ps` for PID/PPID/RSS/CPU/elapsed and `lsof -a -p <pid> -d cwd -Fn` where available. Build ancestry so a `next-server` child inherits its owning `next dev` worktree.
- Open files: `lsof -- <exact-path>`. If `lsof` is missing, errors, or cannot decide, log/cache candidates are blocked.
- Memory: macOS `vm_stat`, `sysctl vm.swapusage`, and `memory_pressure -Q` when available; provide a limitation elsewhere rather than guessing.
- Disk: Python `stat`/tree sizing with bounded, non-symlink traversal.
- Docker: `docker system df` only. Absence or daemon failure is reported and never blocks the non-Docker audit.

Never emit full process commands. Normalize process evidence to PID, executable/category, cwd/worktree, RSS, CPU, and age. Do not read or emit process environments.

## Classification model

Each finding has one status:

- `eligible`: allow-listed and all safety checks passed;
- `blocked`: otherwise allow-listed but ownership, age, type, path, or tool evidence is insufficient;
- `report_only`: intentionally never mutated by this MVP;
- `active`: normal generated state owned by a live process;
- `normal`: expected project state not worth cleaning.

Each record includes category, sanitized display path, canonical internal path, bytes, age, reason codes, and evidence. Internal paths may be stored in a local plan but JSON output must never include secrets or arbitrary command lines.

## Allow-list policy

### Inactive logs

Accept only a regular non-symlink file whose resolved parent is a registered worktree’s `.dev-logs/`, whose name ends in `.log`, and for which exact-path `lsof` reports no opener. It becomes eligible when:

```text
(size >= 512 MiB and age >= 24 hours) or age >= 14 days
```

The current 10.3 GB `backend-screen.log` motivates the large-file override while the 14-day rule handles forgotten ordinary logs. Active logs and uncertain ownership are blocked.

Worktree dirtiness does not by itself block an exact log candidate: `.dev-logs/` is ignored runtime output and file-level openness is revalidated. Dirtiness still blocks automatic cache cleanup and every Git/worktree mutation.

### Inactive Turbopack cache

Accept only the exact directory suffix `frontend/.next/dev/cache/turbopack` inside a registered worktree. It becomes eligible only when it is at least 24 hours old and process discovery proves that worktree has no active Next/frontend process. Treat the whole directory as one candidate; never traverse a symlink while sizing or deleting it.

A dirty worktree makes its Turbopack cache report-only in the MVP, even though the cache is generated, because preserving the developer’s current iteration state is more important than reclaiming it automatically.

All other `.next` content is report-only in the MVP.

## Plan integrity and drift control

Use a versioned JSON schema. Compute the plan ID as SHA-256 over canonical JSON containing the schema version, repository identity, creation timestamp, and candidate fingerprints, excluding the `planId` field itself.

Fingerprint files with canonical path, file type, device, inode, size, and nanosecond mtime. Fingerprint directories with the root stat plus a deterministic aggregate of contained regular-file relative paths, sizes, and mtimes without following symlinks. Reject unsupported file types.

Apply validates the plan ID before reading candidate paths as instructions. Then validate every candidate against the current filesystem and current ownership state. Use an all-before-any preflight so a stale second candidate cannot cause a partial first deletion. Filesystem errors during the actual deletion are still possible; report partial execution accurately and exit non-zero.

## Deletion implementation

- Use `Path.unlink()` for eligible logs.
- Use a custom non-symlink recursive remover for the exact eligible Turbopack directory; reject any symlink encountered rather than following or unlinking it.
- Do not invoke `rm`, `find -delete`, Docker prune, Git worktree removal, or process signals.
- Do not delete parent directories other than the exact planned Turbopack root.
- After each successful deletion, calculate reclaimed bytes from the audited fingerprint and label them as expected; also report the path’s absence. Do not claim filesystem free-space delta because concurrent activity makes it unreliable.

## Reporting

Human output should lead with:

1. whether this was audit or apply;
2. total eligible, blocked, report-only, and active bytes/counts;
3. exact eligible candidates and reasons;
4. safety limitations;
5. the plan ID and explicit apply command for a saved plan;
6. zero-mutation statement for audit or actual deletion totals for apply.

JSON output uses stable top-level keys: `schemaVersion`, `mode`, `repo`, `summary`, `findings`, `limitations`, and either `plan` or `applyResult`.

## Compatibility and security

- Target the current macOS development host first while degrading safely on Linux.
- Use subprocess argument arrays with `shell=False` and bounded timeouts.
- Never load `.env*`, Docker inspect environments, browser storage, database rows, or full process command lines into output.
- Refuse cloud URLs and non-local repository roots as cleanup targets.
- Treat every missing ownership signal as a reason to block deletion.

## Rollback and operational boundary

Audit and plan generation are reversible and non-destructive. Apply deletes generated logs/caches and cannot restore them; the plan review plus all-before-any revalidation is the rollback boundary.

After the separately approved reference cleanup rehearsal, implementation validation must never apply to the live project. Exercise the implemented apply path only in temporary test fixtures. After the skill ships, a separate user-approved invocation may apply a freshly reviewed live plan.

## Important trade-offs

- Docker build cache could reclaim substantial disk, but automatic pruning can affect unrelated work. Keep it report-only.
- Removing old worktrees could reclaim more than caches, but worktree age does not prove abandonment. Keep all Git mutation report-only.
- A one-command destructive cleanup would be convenient but weakens review and TOCTOU protection. Require audit plan plus confirmation instead.
- Cross-platform ownership detection is imperfect. Prefer a blocked candidate over portable but unsafe guessing.
- A sibling feature worktree would provide stronger Git isolation, but the user explicitly declined it for this project-tooling-only change. Compensate with path-level edit ownership, before/after status comparison, and no staging or cleanup of unrelated files.
