# SmallKhoj 侧边栏设计 · 交接给 Open Design AI

> 本文档记录一次完整的设计探索过程与最终成果，交给 Open Design 里的 AI 继续优化。
> 目标：让侧边栏拥有「阳光穿透水体的中海蓝 + 暖沙 + 水纹阳光感」的真实质感。
> 当前状态：**已有一个可用的方案**（真实水材质底图 + 代码图标），但仍是「图片」,
> 希望看看 Open Design 能否做得更好。

---

## 1. 目标与硬约束

### 设计目标
把 SmallKhoj 桌面应用的**左侧导航栏**，做成「**阳光穿透清澈中海海水**」的感觉：
- 深邃又透亮的中海蓝（阳光穿水后剩下的短波长蓝光）
- 阳光穿透水体的光柱
- 水面波纹/焦散光
- 底部融入暖沙色（沙滩的舒服感）
- 明亮但不刺眼，是一个让人想长时间待的工具

### 视觉参考（灵魂图）
- **`IMG_20260506_194102.jpg`** —— 用户提供的海水沙滩照片，是所有色彩的「唯一真相」。
- 这张图定义了「水」「光」「沙」应该是什么样。

### 硬约束（不能违反）
1. **不能用紫蓝**（hue 250-265）。之前项目用的是紫蓝（`oklch(... 260)`），用户明确不喜欢。必须是偏青的蓝（hue 180-215，蓝绿之间）。
2. **底部必须有暖沙色**，不是白、不是灰。
3. **目前代码暂不能合并**（有别的工作分支在改前端 `product-shell.tsx`）。所以现阶段产出以「设计稿/图片/方案」为主，代码改动作为补丁备好，等可合并时再落。
4. **impeccable 设计规范**：不要 glassmorphism、不要渐变文字、不要霓虹发光、不要大面积模糊光斑。圆角 11-16px 区间。

## 2. 探索路径与关键决策（避免重复踩坑）

这次探索走了几条路，每条都有明确的结论。**请勿重复已验证失败的方向。**

### ❌ 路径 A：纯文字生图提示词（失败）
- 用自然语言描述「中海蓝 + 暖沙 + 光感」让 GPT Image 生图。
- **失败原因**：生图模型对「中海蓝 vs 紫蓝」「暖沙 vs cream」的精确色相控制极弱，默认蓝色滑向紫蓝/navy。
- **教训**：抽象形容词（subtle/faint/clean）会让模型「少做事」，产出全白线框。

### ❌ 路径 B：CSS 多层叠层（失败）
- 用 `linear-gradient` + 多个 `radial-gradient` 伪元素叠水纹和阳光。
- **失败原因**：在用户的浏览器环境里，多个绝对定位 div + z-index 的层叠会被合并/丢弃，水纹阳光根本渲染不出来。
- **教训**：复杂材质不要靠 CSS 层叠，渲染不可靠。

### ✅ 路径 C：原图客观提取色值（成功，是地基）
- 用 k-means 聚类 + 纵向渐变采样，从参考照片里**程序化提取真实颜色**。
- **关键发现**（用户一句话点破的）：图里的蓝**不是一个色号**，是「深蓝(偏紫 hue 258) → 青蓝(hue 184-207) → 暖沙(hue 64)」的**连续渐变带**。光反射和半透明混合造出了「透亮青蓝」，单独拎一个 hex 反而不准。
- **教训**：别找「一个中海蓝 hex」，要用「色相区间 + 渐变」。

### ✅ 路径 D：原图当参考图 + 提示词生图（成功，是当前方案）
- 把参考照片作为 GPT Image 的参考图，让模型从图里**直接取色取质感**。
- 比纯文字提示词准得多，因为照片是色彩真相。
- 产出了带真实水质感的方形图（`gen_src.png`）。

### ✅ 路径 E：真实生图当材质贴图 + 代码叠图标（当前可用方案）
- 把生图裁成侧栏比例的「纯水材质底图」`rail_texture.png`。
- 图标、激活态、hover 用代码（lucide 图标库）叠在上面。
- **这是「图当材质 + 代码当交互」的标准做法**，已验证可渲染、好看。
- 产物：`rail_polished.html`（精致预览）、`/tmp/rail_polished_shot.png`（截图）。

### ⚠️ 路径 F：Pillow 直接画（部分可行但不推荐）
- 用 Python Pillow 画渐变 + 波浪线 + 阳光。
- 能画出来，但**质感是死的**（波浪是几何正弦，阳光是硬叠），不如真实生图有「呼吸感」。
- 教训：真实材质（焦散、颗粒、光散射）代码画不出，必须靠图。

## 3. 色彩真相（地基，所有设计都基于此）

### 真实色相区间（从参考照片提取，OKLCH）
| 区域 | 色相 hue | 明度 L | 彩度 C | 是什么 |
|---|---|---|---|---|
| 深水（顶） | 254-260 | 0.43-0.54 | 0.10-0.13 | 深蓝（偏紫的深水） |
| 中海蓝 | 184-207 | 0.62-0.77 | 0.08-0.11 | **透亮青蓝/中海蓝（核心主调）** |
| 浅水/海雾 | 112-167 | 0.79-0.84 | 0.03-0.05 | 蓝+沙的半透明混合 |
| 暖沙（底） | 64-89 | 0.81-0.85 | 0.025-0.045 | 暖沙白 |

### 给落地用的 token（OKLCH）
```
--bg:         oklch(0.26 0.095 226)   /* 深水顶 */
--deep:       oklch(0.34 0.105 220)   /* 深 */
--primary:    oklch(0.52 0.115 208)   /* 中海蓝（主调）*/
--bright:     oklch(0.70 0.110 198)   /* 透亮青 */
--pale:       oklch(0.82 0.085 195)   /* 浅水 */
--sand-trans: oklch(0.88 0.060 120)   /* 暖沙过渡 */
--sand:       oklch(0.90 0.045 80)    /* 暖沙 */
--sand-base:  oklch(0.91 0.040 70)    /* 沙底 */
```

### 关键禁忌色（绝对不用）
- `oklch(... 260)` 附近的紫蓝 —— 这是旧主题的颜色，用户明确不喜欢
- 纯白 `oklch(1 0 0)` 当底 —— 太苍白
- 纯灰暖沙 —— 必须带 hue 60-90 的暖调

## 5. 给 Open Design AI 的明确任务

### 现状评估
当前方案**可用**，但用户说「这只是图片」，想知道能否更好。具体的不满/可优化点：
1. 底图是**固定尺寸图片**，高屏幕会变形/露馅（拉伸或接缝）
2. 水纹和阳光是**静态的**，没有「水的呼吸感」
3. 整体质感依赖单张生图，**不够精致/可控**

### 希望你（Open Design AI）探索的方向
1. **能否生成更高质量的水材质底图？**（更高分辨率、更可控的焦散/光纹、边缘可平铺）
   - 如果你能调用生图模型（配了 BYOK），可基于 `IMG_20260506_194102.jpg` + 下面的提示词重生
   - 目标：纵向可平铺（top/bottom 边缘无明显特征），纯材质无 UI 元素
2. **能否把水纹/阳光做成可动效的？**（极慢的波纹漂移，配 `prefers-reduced-motion`）
3. **能否用 SVG/程序化方式复现真实水感？**（如果可行，就不用依赖图片，解决高屏幕问题）
   - 注意：之前纯 CSS 失败了（渲染丢层）。SVG 硬画可行但质感偏死。
4. **整体设计系统**：侧栏定了之后，主内容区、聊天气泡、按钮的颜色该怎么配？（用同一套色相）

### 如果你重生底图，用这个提示词（已验证有效）
配合参考图 `IMG_20260506_194102.jpg`：
```
TEXTURE TASK: Create a PURE BACKGROUND TEXTURE — NO UI elements, NO buttons, NO icons, NO text.
A tall narrow water-and-sand strip (portrait, taller than wide).
TOP 15%: deep ocean teal-navy. MIDDLE 60%: transparent mid-sea cyan-blue getting brighter downward, with realistic underwater light shaft angling from top-left, and water caustic ripple lines. BOTTOM 25%: warm beach sand texture.
The blue MUST be the photo's cyan-teal (between blue and green), NOT purple, NOT navy.
The bottom MUST be warm sand, NOT white, NOT gray.
Make top/bottom edges seamless-friendly (no obvious features at edges) for vertical tiling on tall screens.
Photorealistic water material, soft realistic light, no neon, no glassy blur. High resolution.
```
API 用 `size: 1024x1536`（竖图），不要用方形（方形要裁剪，损失边缘）。

### 成功标准
- 水的质感比当前 `rail_texture.png` 更真实/更精致
- 解决高屏幕变形问题（要么可平铺，要么程序化）
- 仍然遵守色彩真相（青蓝不是紫蓝，底部是暖沙）
