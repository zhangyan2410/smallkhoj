# Bug Diagnosis Capsule: WebDriver URL Match Tab Selection

| Field | Content |
|------|------|
| **1. Symptom** | `./twd --url-match 127.0.0.1:3000` can inspect a stale localhost tab instead of the user's visible tab. Expected: choose the active matching tab when possible, otherwise fail with candidates. Actual: a broad match can silently choose the first matching session. |
| **2. Evidence** | User screenshot showed the real chat sidebar with three DMs, while `./twd --url-match 127.0.0.1:3000` read an old DM page with one DM. Source read: `twd.py::choose_session` filters by URL then returns `(active or sessions)[0]`; `tmwebdriver_core.py` drops `active/windowId` from extension `ext_ready` / `tabs_update` payloads. Real verification also showed two extension connections: one `tabs_update` from a different extension connection could mark the selected tab disconnected, after which `execute_js` silently switched to another alive session. |
| **3. Hypothesis / Root Cause** | Confirmed root cause: `twd.py::choose_session` filtered sessions by substring and then returned `(active or sessions)[0]`. For extension sessions, `tmwebdriver_core.py` rebuilt session info from `ext_ready` / `tabs_update` and only retained `url/title/type`, so cached candidates often had no `active` signal. Broad localhost matches therefore silently chose the first cached matching tab. Secondary root cause: core treated every extension `tabs_update` as a global complete tab list, so multiple extension/browser connections could disconnect each other's sessions; explicit CLI calls could then be silently executed on a fallback alive session. |
| **4. Diagnostic Strategy** | Trace `--url-match` from wrapper to CLI selector, compare cached session metadata with live extension `tabs` command metadata, then extract selection logic into a pure unit-testable function. |
| **5. Timeout Strategy** | If live active-tab metadata cannot be obtained through existing extension commands inside the allowed write scope, implement ambiguity failure for multiple URL matches and document the focused-window limitation. |
| **6. Warning Strategy** | Stop if the fix requires changing chat UI/API files or changing Chrome extension files outside the requested write scope. Do not mask ambiguity by sorting or picking newest without a reliable user-visible active signal. |
| **7. User-Visible Interaction Correction** | CLI results should include the selected tab URL, and ambiguous broad matches should return `ok=false`, code `AMBIGUOUS_TAB`, with candidate tab IDs and URLs. |
| **8. Acceptance** | Focused unit tests for single match, active match, and ambiguous multi-match; `./twd --compact tabs`; manual `eval` against a more specific URL match verifying returned `tabUrl`. |
