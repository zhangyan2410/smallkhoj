# Task Board DnD Hydration Mismatch

## Reporter

Operator reported a Next.js console hydration error on the Tasks page.

## Reproduction

Open `/tasks` in the browser.

Expected:

- Server-rendered sortable task cards and hydrated client task cards have matching attributes.

Actual:

- React reported a hydration mismatch on task card `aria-describedby`.
- Server markup used a counted dnd-kit id such as `DndDescribedBy-6`.
- Client hydration used a different counted id such as `DndDescribedBy-0`.

The pasted trace also showed a `data-qk-id` attribute on a video element. That attribute is consistent with external browser extension mutation. It is not generated by SmallKhoj, but React still reports it as a hydration attribute mismatch when the extension mutates the server HTML before hydration.

## Root Cause

`frontend/components/task-board.tsx` rendered `DndContext` without a stable `id`.

dnd-kit derives the draggable hidden-text id with `useUniqueId("DndDescribedBy", id)`. Without an explicit context id, it falls back to a process/render-order counter. SSR and client hydration can observe different global dnd-kit counter state, especially when other DnD surfaces have rendered first. That produces different `aria-describedby` attributes for the same sortable task card.

## Fix

Added a stable task-board DnD context id:

```tsx
const TASK_BOARD_DND_CONTEXT_ID = "smallkhoj-task-board"

<DndContext id={TASK_BOARD_DND_CONTEXT_ID} ...>
```

This makes sortable task cards render `aria-describedby="smallkhoj-task-board"` on both server and client.

For video artifact previews, added `suppressHydrationWarning` to the `<video>` element in `MemoryArtifactPreview`. This prevents extension-injected attributes such as `data-qk-id` from surfacing as application hydration errors.
