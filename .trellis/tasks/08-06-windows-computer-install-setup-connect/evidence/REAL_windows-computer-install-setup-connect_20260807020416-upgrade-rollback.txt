## §5.3 活跃 lease 冲突拒绝 — PARTIAL(服务器侧 PASS, 客户端预检缺)
- 服务器侧: connect/connect 端点在有 active lease 时返回 409, 客户端正确 surface 为
  state.status=error + lastError 匹配 409, exit 1. 冲突保护实际生效 ✅
- 客户端预检缺口: main.ts launchManagedDaemon (line 237) 仅检查本地 pid (isDaemonRunning),
  不在 connect 前预查远端 activeDaemonId/leaseExpiresAt 来给出 stop/wait/retry 的可操作提示,
  而是直接发 connect 让服务器拒绝. 功能上阻止了重复启动(服务器兜底), 但 UX 上未提供
  acceptance §5.3 要求的"停止/等待/重试"显式提示.
- 判定: 冲突阻止 = PASS(服务器兜底); 客户端可操作提示 = code-missing(记 BLOCKED-client-hint)

## §6.1 升级:旧版本目录保留到新进程健康 — BLOCKED(code-missing) ❌
证据: release-artifacts/smallkhoj-daemon/install.ps1 line 76:
  if (Test-Path $versionRoot) { Remove-Item -LiteralPath $versionRoot -Recurse -Force }
  Move-Item -LiteralPath $staging -Destination $versionRoot
- 安装器在 stage 新版本成功后, 移动前直接递归删除整个旧版本目录, 没有保留旧版本直到新进程健康.
- 即"原子切换"部分实现(staging→move→active.json swap), 但"旧版本保留到新进程健康"未实现.
- PRD/acceptance §6.1 "旧版本目录保留到新进程健康" 无法满足 → BLOCKED(installer-line76)

## §6.2 禁止隐式降级 / 显式 rollback — BLOCKED(code-missing) ❌

- `aura rollback` → 无此命令, 输出通用 usage (rollback_exit=0 但仅打印 help, 未执行回滚)
- `aura --help` 无 rollback/downgrade/force 任何子命令或选项

- 判定: rollback 命令未实现, 版本比较逻辑未实现 → BLOCKED(no-rollback-command)
