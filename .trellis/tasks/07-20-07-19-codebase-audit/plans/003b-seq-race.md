## Why this matters

Plan 004 made `messages.seq` a real PostgreSQL identity column
(`GENERATED BY DEFAULT AS IDENTITY`). The app still manually assigns
`seq = max(seq) + 1` at three call sites — a read-modify-write race that
makes concurrent message sends collide on the unique constraint and 500.
Now that the DB can assign `seq` itself, removing the manual assignment
eliminates the race.

This was the original BLOCKED finding; plan 004 was the unblocker.

## Current state (post-004)

**`backend/models/slock.py:270`** — already updated by plan 004:
```python
seq: Mapped[int] = mapped_column(
    BigInteger,
    Identity(always=False, start=1, increment=1),  # GENERATED BY DEFAULT
    unique=True,
)
```

**Three call sites still assign `seq` manually:**

1. `backend/routers/public_api.py:1996` — supervisor message post:
   ```python
   seq_result = await db.execute(select(func.coalesce(func.max(Message.seq), 0)))
   msg = Message(..., seq=int(seq_result.scalar() or 0) + 1)
   db.add(msg); await db.flush()
   ```

2. `backend/routers/agent_api.py:1839,1852` — agent send:
   ```python
   seq_result = await db.execute(select(func.coalesce(func.max(Message.seq), 0)))
   last_seq = seq_result.scalar() or 0
   ...
   msg = Message(..., seq=last_seq + 1)
   ```

3. `backend/services/reminder_scheduler.py:41-43, 87` — helper + reminder firing:
   ```python
   async def _next_message_seq(db: AsyncSession) -> int:
       result = await db.execute(select(func.coalesce(func.max(Message.seq), 0)))
       return int(result.scalar() or 0) + 1
   ...
   message = Message(..., seq=await _next_message_seq(db))
   ```

## Steps

### Step 1: Remove manual `seq=` in public send

In `backend/routers/public_api.py` around line 1996 (`create_channel_message`):
- Delete `seq_result = await db.execute(select(func.coalesce(func.max(Message.seq), 0)))`.
- Remove `seq=int(seq_result.scalar() or 0) + 1,` from the `Message(...)` call.
- After `await db.flush()`, add `await db.refresh(msg)` so the DB-assigned `seq` is loaded.
- Find any later use of `msg.seq` (event payload, activity record, response) and confirm it reads from the refreshed `msg`. If a local variable captured the old value, replace with `msg.seq`.

### Step 2: Same in agent send

`backend/routers/agent_api.py` ~1839-1852 — same change. Delete `seq_result`/`last_seq`, remove `seq=` kwarg, add `await db.refresh(msg)`.

### Step 3: Remove `_next_message_seq` helper and its usage

`backend/services/reminder_scheduler.py`:
- In `fire_due_reminders`, find `message = Message(..., seq=await _next_message_seq(db))` (~line 87) and remove the `seq=` kwarg.
- After `db.flush()`, `await db.refresh(message)` so `message.seq` is populated for the activity payload (~line 157).
- Delete the `_next_message_seq` helper (lines 41-43).

### Step 4: New test asserting DB-assigned seq

Write `backend/tests/test_message_seq_auto_assign.py`. The key property: creating a `Message` without `seq=` and flushing produces a non-None `seq`.

Two approaches depending on what test infrastructure exists:
- **Real-DB test** (preferred): model after `test_chat_read_cursors_postgres_http.py` which uses real Postgres. Create a message without `seq`, flush, assert `msg.seq` is a positive int. Also test two concurrent inserts produce distinct seqs.
- **Mock test** (fallback if no real-DB setup): mock the flush to verify the `Message(...)` constructor is called WITHOUT `seq=` keyword. Weaker but proves the code change.

**Verify**: `cd backend && uv run pytest tests/test_message_seq_auto_assign.py -q` → pass.

## Maintenance notes

- After this lands, `messages.seq` is DB-assigned. New code should NEVER pass `seq=` to `Message(...)`.
- Plan 004 left the column as `BY DEFAULT` (permits explicit override). If you want to tighten to `ALWAYS` later (rejecting explicit inserts entirely), that's a separate migration after this plan verifies the manual-assignment removal works in production.
- The reminder scheduler still uses `Base.metadata.create_all` defensively in `create_tables` (plan 004's decision); that's unrelated to this plan.
