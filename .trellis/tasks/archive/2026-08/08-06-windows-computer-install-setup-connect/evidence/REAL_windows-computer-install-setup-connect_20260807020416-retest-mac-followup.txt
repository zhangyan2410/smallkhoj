## R-4 lease preflight(DAEMON_LEASE_ACTIVE + stop/wait/retry)→ PASS(实机,关键)
- **前置发现(如实记录)**:首轮测 lease preflight 失败,因运行中的 backend(8/6 启动,`python main.py` 无热重载)是旧代码,返回裸 `{"detail":"Computer already has an active daemon"}` 无 reasonCode。**重启 backend(`./dev.sh restart`,加载新 agent_api.py)后行为正确**。这是真实运维要点:backend 改动必须重启,无热重载。
- **重启后实测**:setup win-lease2 → connect(online,computer 78190411)→ stop 本地 daemon(进程退出,但服务器 lease 90s 内仍有效)→ 立即 `POST /computers/{id}/reconnect-command` → **HTTP 409 + 完整结构化冲突**:
  ```json
  {"detail":{"ok":false,"reasonCode":"DAEMON_LEASE_ACTIVE",
  "message":"This computer has an active daemon lease. Stop the existing daemon gracefully, wait for the lease to expire, then retry.",
  "computerId":"78190411-...","activeDaemonId":"295c7bd1-...",
  "leaseExpiresAt":"2026-08-07T08:34:31.226773+00:00","retryAfterSeconds":59,
  "recoveryActions":["stop","wait","retry"]}}
  ```
- **ticket 在冲突前未被创建/消费**(reconnect-command 直接 409,无 connectToken 返回)→ 符合 PRD R12 + R13(冲突时不创建 ticket + 给可操作恢复提示)✅
- daemon 侧(daemon.ts:1001)在 409 时检查 `detail.reasonCode === 'DAEMON_LEASE_ACTIVE'` 消费该字段。
