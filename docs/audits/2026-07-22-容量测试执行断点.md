## 阻塞原因（实测诊断，非推测）

**当前网络访问 PyPI 带宽极低（~7 KB/s）**，导致 backend Dockerfile 的
`RUN pip install uv && uv sync`（需下载 ~400MB 依赖）反复
`ReadTimeoutError`，3 次构建全部失败。

实测数据：
- DNS 解析正常（`files.pythonhosted.org → 151.101.192.223`）
- HTTP 连接正常（能收到响应，不是连不上）
- 小包下载成功但极慢（requests 73KB 耗时 ~10s ≈ 7KB/s）
- 本机（macOS）和 colima 容器内表现一致，非容器独有问题
- backend 全量依赖 ~400MB，按 7KB/s 需 ~16 小时，不现实

结论：这是网络状况问题（可能 VPN 限速或运营商问题），不是代码/工具问题。
不影响 PR #1（代码修复 + PG 迁移冒烟已 push）。

### 已知的构建坑（避免重蹈）

1. **backend Dockerfile 层顺序问题**：`COPY backend/`（L3）在
   `RUN uv sync`（L5）之前，导致代码变就缓存失效，每次都全量重下依赖。
   这是 Dockerfile 问题，不是本轮要改的（改了会污染容量测试的 candidate
   clean 状态）。靠网络恢复后一次成功构建即可。
2. **`--network=host` 在 colima 下不可用**：buildkit 容器走默认 NAT，
   `--network=host` 反而连不上 PyPI。
3. **`docker images | grep` + `&& echo` 判断陷阱**：镜像不存在时
   `docker images` 返回空但 exit 0，`&&` 会误报成功。务必检查
   `.ID` 字段是否非空。

### 第 5 步：smoke 流程验证

```bash
uv run --project backend --no-sync python3 scripts/local_capacity_probe.py \
  --profile smoke --steady-sse 10 --spike-total-sse 15 --active-users 3 \
  --duration-seconds 60 --output /tmp/capacity-smoke.json
```

smoke acceptance 必含 `NON_FORMAL_CAPACITY_PROFILE`（正常）。重点确认：
无 fixture setup error、无 SSE 连接失败、无 DB 连接失败。

smoke 需要 env：`API_BASE`（caddy 端口 38190）、`CAPACITY_DATABASE_URL`、
`CAPACITY_DATABASE_SCOPE=disposable`、`CAPACITY_COMPOSE_PROJECT`、
`PUBLIC_API_KEY`、`AUTH_BRIDGE_SECRET` 等（见 probe load_config）。
可能需要 socat forward 让 probe 连到容器内 PG（probe 要求 loopback PG）。

### 第 6 步：formal 容量测试
