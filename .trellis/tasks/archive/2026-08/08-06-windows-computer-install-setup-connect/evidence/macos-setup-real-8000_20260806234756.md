## Setup 幂等

安装后在全新 runtime root 执行两次：

```bash
HOME="$ROOT/home" \
AURA_INSTALL_ROOT="$ROOT/runtime-root" \
SLOCK_AGENT_CREDENTIAL="$ROOT/credential.json" \
AAA_DAEMON_MACHINE_ID_FILE="$ROOT/machine-id" \
  "$ROOT/bin/aura" setup --name "install-real-8000-20260806234756" --server-url "http://127.0.0.1:9"
```

两次输出均为：

```text
[Aura] Setup complete for install-real-8000-20260806234756
Config: .../runtime-root/config.json
Mode: managed
```

两次 machine ID 相同（原值不写入仓库）：

```text
MACHINE_ID_IDEMPOTENT=true
CREDENTIAL_CREATED=false
```

`server-url=127.0.0.1:9` 是不可达地址，专门证明 Setup 不需要访问服务器；Setup 阶段没有
创建 credential。Connect 阶段才会生成并持久化 machine token。

两次 Setup 都以退出码 `0` 完成；停止状态的 `aura status --json` 以退出码 `1` 返回，
但 stdout 是单个可解析 JSON（这是预期的“未运行”状态码，不是命令失败）。安装后 fake-upstream
Connect 流程以退出码 `0` 完成，协议错误为 `null`。

## 安装产物的 Connect / register / heartbeat

为避免把 fake upstream 误写成产品 Online，使用刚安装的 `.../bin/aura` 连接一次随机端口
本地 HTTP fake upstream。fake server 做了严格断言：

- `/internal/agent-api/daemon/connect` 必须带脱敏的 connect ticket，payload `daemonVersion=0.2.6`；
- 返回 fake machine token 后，`/daemon/register` 和 `/daemon/heartbeat` 必须使用该 token；
- 等待 daemon heartbeat 定时器（约 15 秒），再检查 daemon 进程仍存活和本地状态。

脱敏结果：

```json
{
  "base": "http://127.0.0.1:<ephemeral-port>",
  "connectReceived": true,
  "registerReceived": true,
  "heartbeatReceived": true,
  "daemonVersion": "0.2.6",
  "registerWorkspaceCount": 0,
  "heartbeatStatus": "online",
  "childAliveAfterHeartbeat": true,
  "credentialCreatedAfterConnect": true,
  "credentialKeys": ["agent_id", "machine_id", "server_id", "server_url", "token", "ws_url"],
  "machineIdPersisted": true,
  "machineIdReused": true,
  "protocolError": null,
  "stderr": ""
}
```

另以脱敏比较确认 Setup 与 Connect 复用了同一 machine ID；原始 token/UUID 不写入仓库：

```text
CONNECT_MACHINE_ID_REUSED=true
CREDENTIAL_TOKEN_REDACTED=true
```

## 结论边界

- **PASS（Mac 安装产物协议层）：** 安装后的真实 launcher 能完成 connect ticket → machine token → register → heartbeat(`online`)；Connect 后进程保持运行，credential 和 machine ID 持久化。
- **不能宣称：** fake upstream 不是 SmallKhoj backend，不能证明真实数据库写入、服务器 Computer 页面 Online、云端网络、ticket 过期/重连或 Windows PE。
- Windows agent 必须在同一 `main` 候选上使用真实 Windows backend carrier/账号完成 Online/heartbeat、Reconnect、冲突、升级/回滚，并提交脱敏证据后，负责人才能让用户做最终验收。
